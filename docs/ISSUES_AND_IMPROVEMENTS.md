# בעיות ושיפורים — מצב עבודה

הבעיות 1–3 שוחזרו בבדיקות על d85bb48. התיקונים המוצעים עדיין לא יושמו בעותק שנבדק. אין להגיש מסמך זה כאילו שלושה שיפורים כבר הושלמו.

## 1. אובדן הקשר בשאלת המשך

- שחזור: היסטוריה עם שאלה על קטאן, ואחריה ״וכמה צריך כדי לנצח?״ ללא מסנן משחק.
- ממצא: האחזור קיבל רק את השאלה החדשה ומסנן None; ההיסטוריה הגיעה רק לשלב יצירת התשובה.
- משמעות: עלולים להישלף מקטעים ממשחקים אחרים. הבדיקה אינה מוכיחה מה המודל האמיתי היה עונה.
- שיפור מוצע: ניסוח שאלה עצמאית מתוך ההיסטוריה לפני האחזור, או ניהול הקשר משחק מפורש כשאפשר לזהותו בבטחה.
- אימות נדרש: שאלות המשך בכמה משחקים, לרבות שינוי מפורש של המשחק באמצע השיחה.
- מצב: שוחזר; תיקון ותוצאת אחרי — טרם הושלמו.

## 2. אובדן אינדקס בעת כשל בבנייה מחדש

- שחזור: בניית אוסף של 41 מקטעים, ואז הזרקת כשל בשלב יצירת האינדקס בבנייה חוזרת באותו שם.
- ממצא: לאחר הכשל נשארו 0 מקטעים, כי האוסף הקודם נמחק בתחילת התהליך.
- שיפור מוצע: בנייה באוסף חדש, בדיקת הצלחה, ואז מעבר מבוקר אליו; להשאיר את הקודם זמין במקרה כשל.
- אימות נדרש: כשל יזום לפני ובמהלך יצירת embeddings, בדיקת נגישות האוסף הישן, ובדיקה שגם לאחר הפעלה מחדש נבחר האוסף התקין.
- מצב: שוחזר במסד זמני; תיקון ותוצאת אחרי — טרם הושלמו.

## 3. היסטוריה ממשחק קודם לאחר החלפת משחק

- שחזור: בחירת קטאן, הודעה ותשובה, ואז בחירת אונו בממשק Streamlit.
- ממצא: שתי ההודעות הקודמות נותרו בהיסטוריה.
- שיפור מוצע: איפוס ההיסטוריה או שמירת היסטוריה נפרדת לכל משחק. יש להחליט במפורש מה קורה גם במעבר אל ״כל המשחקים״ וממנו.
- אימות נדרש: החלפת משחק בשני הכיוונים ובדיקה שההיסטוריה שנשלחת למודל תואמת להתנהגות שנבחרה.
- מצב: שוחזר עם backend מדומה; תיקון ותוצאת אחרי — טרם הושלמו.

## 4. כשל תעודת אבטחה בהורדת מודל Hugging Face

- מקור הממצא: פלט ההרצה המקומי שצורף, ולא הגרסה הציבורית שנבדקה.
- ממצא: CERTIFICATE_VERIFY_FAILED בעת ניסיון הורדת intfloat/multilingual-e5-small. התהליך נעצר בהגדרת embeddings, לפני שאלות ההערכה.
- פתרון שהוצע: הפעלת truststore בתחילת סקריפט ההרצה, לפני טעינת ספריות החיבור, לשימוש במאגר תעודות מערכת ההפעלה.
- מצב: טרם התקבל פלט שמאשר הורדה והרצה מוצלחות. אין לרשום שהבעיה נפתרה לפני אימות.

## תבנית להשלמת כל שיפור להגשה

1. קלט מדויק וגרסת הקוד לפני התיקון.
2. תשובה, מקורות או הודעת שגיאה שהתקבלו בפועל.
3. הסבר לסיבה והשינוי המדויק בקוד.
4. הרצת אותו מקרה לאחר התיקון ושמירת התוצאה.
5. בדיקת מקרה נוסף כדי לוודא שהשינוי אינו פותר רק את הדוגמה האחת.
