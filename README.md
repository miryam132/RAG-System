# עוזר חוקי משחקי קופסה — RAG

מערכת לשאלות בעברית על חוקי אונו, קטאן, שחמט, שש־בש ורמיקוב. המערכת מאחזרת קטעים ממאגר חוקים, שולחת אותם למודל שפה ומציגה תשובה לצד הקטעים שנשלפו.

## מצב וגרסאות

המערכת משתמשת ב-Gemini גם ליצירת embeddings וגם ליצירת תשובות. מודל ה-embeddings המוגדר כברירת מחדל הוא `gemini-embedding-001`. אין צורך בהורדת מודל מ-Hugging Face. אם קיימת אצלך גרסה מקומית עם Hugging Face, יש לעדכן את קובצי המקור לגרסה זו ולבנות אינדקס חדש לפני השימוש.

בדיקות התשתית המקומיות: 8 עברו, 3 נכשלו. איכות התשובות מול מודל אמיתי עדיין אינה מאומתת בדוח המצורף. פירוט ב-[דוח הבדיקות](tests/TEST_REPORT_HE.md).

## ארכיטקטורה

שלב בניית המאגר (`src/ingest.py`): קריאת קובצי Markdown מתוך `data`, חילוץ metadata, פיצול לפי כותרות `##`, חלוקה באמצעות `SentenceSplitter`, יצירת embeddings ושמירה באוספי Chroma מקומיים בתוך `chroma_db`.

שלב השאלה (`src/rag.py`): קבלת שאלה ומסנן משחק אופציונלי, אחזור עד ארבעה מקטעים, בניית הקשר הכולל משחק וסעיף, יצירת תשובה באמצעות LLM והחזרת תשובה ומקורות לממשק Streamlit.

היסטוריית השיחה נשלחת למודל בשלב יצירת התשובה, עד שש הודעות. בגרסה שנבדקה היא אינה משמשת לניסוח שאילתת החיפוש; לכן שאלות המשך ללא שם המשחק עלולות לאחזר מקורות לא מתאימים.

| רכיב | בחירה ומטרתה |
|---|---|
| Python | טעינה, עיבוד, אחזור וחיבור למודל |
| LlamaIndex | מסמכים, חלוקה, אינדקס ואחזור ברכיבים מוכנים |
| Chroma | אחסון וקטורים מקומי מתמשך וסינון לפי metadata |
| Gemini embeddings, בגרסה הציבורית | המרת מקטעים ושאלות לווקטורים דרך API |
| Gemini LLM, בגרסה הציבורית | ניסוח תשובה מתוך הקטעים שאוחזרו |
| Streamlit | ממשק שיחה ובחירת משחק והגדרת חלוקה |
| Markdown | מאגר קטן וקריא, עם סעיפים ו-metadata |

אלה הסברים להתאמת הרכיבים לפרויקט; לא בוצע מחקר השוואתי שמוכיח עליונות על חלופות.

## התקנה והרצה ב-Windows

פתח טרמינל בשורש הפרויקט. סביבת הבדיקה המקומית השתמשה ב-Python 3.12.14; אין בכך אישור לתאימות מלאה לכל גרסת Python אחרת.

```powershell
python -m venv .venv
.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

אם כבר קיים `.env`, השאר אותו ואל תדרוס אותו. ערוך את הקובץ והגדר `GOOGLE_API_KEY` אמיתי. אין להעלות אותו ל-GitHub. שמות המודלים האופציונליים בקובץ הדוגמה נקראים מתוך `src/config.py`.

בנה אינדקס אחד והפעל את הממשק:

```powershell
.venv\Scripts\python.exe src/ingest.py c512
.venv\Scripts\python.exe -m streamlit run src/app.py
```

כדי לבנות את כל שלוש הגדרות החלוקה:

```powershell
.venv\Scripts\python.exe src/ingest.py
```

בגרסה הנוכחית בנייה חוזרת מוחקת תחילה את האוסף בעל אותו שם. גבה מסד קיים לפני בנייה חוזרת אם ברצונך לשמור אותו. שינוי מודל embeddings מחייב בניית אינדקס תואם; אין להשתמש בווקטורים מהמודל הקודם לחיפוש עם המודל החדש.

## שימוש

בחר הגדרת chunking ומשחק, או ״כל המשחקים״. שאל שאלה מפורשת, למשל: ״כמה קלפים מקבל כל שחקן באונו בתחילת המשחק?״. פתח ״מקורות״ כדי לראות את המקטעים שנשלפו. ציון הדמיון אינו הסתברות לנכונות התשובה. המקורות המוצגים הם המקטעים שנשלפו, ואין בקוד אימות שכל אחד מהם שימש בפועל בתשובה.

לעת עתה מומלץ לנקות שיחה בעת החלפת משחק ולציין את שם המשחק בשאלות המשך, עד לתיקון הכשלים המתועדים.

## בדיקות

```powershell
.venv\Scripts\python.exe -m pip install pytest
.venv\Scripts\python.exe -m pytest tests/test_system.py -v
.venv\Scripts\python.exe tests/live_evaluation.py
```

הפקודה הראשונה של הבדיקות אינה פונה ל-Gemini: היא משתמשת ב-Chroma וב-LlamaIndex אמיתיים ובתחליפי מודלים. שלוש בדיקות נכשלות על הגרסה הציבורית שנבדקה. לאחר שינוי קוד או מעבר לספק מודלים אחר יש לבדוק את התאמת הבדיקות.

הבדיקה החיה מפעילה את המודלים המוגדרים ב-`config.py`, בונה מסד זמני ונפרד, ושומרת תשובות ומקורות ב-`tests/live-results.json`. ציפיות התשובה בקובץ הן אמת מידה לבדיקה ידנית, לא תוצאות. שימוש ב-API עשוי להיות כרוך בעלות. נדרש לעבור ידנית על התשובות לפני דיווח על הצלחה.

## מגבלות ומצב ההגשה

- מאגר החוקים הוא סיכום קטן; בקבצים לא מצוינים קישורים למקורות רשמיים או מהדורות. יש להוסיף ולבדוק אותם לפני הצגת המאגר כמקור מוסמך.
- הוראות למודל להימנע מהמצאות קיימות, אך התנהגות זו דורשת בדיקה חיה.
- סינון metadata לפי משחק ממומש. Reranking אינו ממומש.
- קיימות שלוש הגדרות של אותה שיטת חלוקה; מדידת איכות השוואתית עדיין חסרה.
- להגשה עדיין נדרשות תשובות אמיתיות ומקורות ללפחות חמש שאלות, ותיעוד של לפחות שלוש בעיות עם שיפורים שבוצעו ואומתו. הטפסים המצורפים אינם תחליף להשלמתם.
